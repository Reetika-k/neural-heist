## 2026-10-20 – Step 3: guards that patrol and see
Prompt (README step 3, both parts): "Add two guards that walk between patrol points. Each guard has a visible vision cone 8 units long and 60 degrees wide. Walls block vision. If the player is inside the cone, a suspicion meter above the guard fills. When it is full, show 'CAUGHT' and a Restart button." + "Give the guards a state machine: Patrol, Suspicious, Search, Chase. In Search, the guard walks to the player's last seen position using A* pathfinding on a grid, looks around, then returns to patrol. Show the current state as an icon above each guard: nothing, ?, eye, !."
Result: worked first time (16/16 unit tests, 14/14 browser checks). Design decisions the assistant made and explained:
- The two prompts conflict (meter full → CAUGHT vs a Chase state). Resolved as: meter full → **Chase**; the guard re-plans an A* route to the player every 0.3 s and catches on contact (0.7 units). Chase speed 3.4 is below the player's 4.0, so a player who runs and breaks line of sight can escape; the guard then **Searches** the last-seen spot.
- Pure modules: `astar.js` (Manhattan heuristic, plus BFS as the correctness baseline), `vision.js` (cone test + wall-blocked line of sight + the clipped cone polygon used for drawing), `guard.js` (state machine). `render.js` only draws: cone mesh rebuilt each frame from the clipped polygon, colour white → yellow → red with suspicion, HTML tag with icon and meter.
- Suspicion fills faster up close (×2 at point-blank) and slower when sneaking (×0.55), and decays out of sight.
Tests: A* equals BFS path length on 300 random mazes and expands fewer cells; edge cases (start = goal, wall goal, out of bounds, sealed rooms); vision in/out of angle and range, blocked by walls, cone clipped at walls; each state transition including Search → Patrol after looking around; sneaking slows the meter; chase catches a still player but not one behind a wall.

## 2026-10-20 – Step 5: Mission 1 Lab (image classifier) and drone
Prompts (README step 5): "Create a Lab screen for Mission 1. Show 30 camera snapshot images... The player drags each one into a 'Guard' or 'Civilian' box. Then a Train button trains a ... KNN classifier ... Show training accuracy and accuracy on 10 held-back test images. If the player labelled fewer than 10 images, warn that the model may overfit." + "In Mission 1, add a drone teammate that flies ahead. For each character it sees, it runs the trained classifier and marks guards in red. Use the real model output, so a badly trained model really misses guards. Show the drone's confidence above each character."
Result: worked (32 unit tests, 29/29 browser checks). What was built and why:
- No snapshot images existed, so `src/lab/snapshots.js` generates 32×32 "CCTV" pixel images procedurally from a seed: guards (navy uniform, usually a red visor, often a cap, gold badge) and civilians (varied clothes), with deliberate hard cases (off-duty guards; civilians in dark coats, sunglasses, red scarves) plus noise and lighting. Every character in the mission carries its own snapshot, so the drone classifies the same kind of image the player labelled.
- `src/lab/classifier.js`: k-NN (k = 3, distance-weighted vote) on a 105-number feature vector (the centre crop averaged into 4×4 cells). Before wiring it in, the assistant measured how label quantity and quality change accuracy on 400 unseen images: 30 correct labels 88%; 10 labels 75%; 4 labels ~60%; 20% mislabelled 74%; 40% mislabelled 53%. That curve is what makes the Lab meaningful.
- Labelling is click-to-cycle (Guard → Civilian → clear) instead of drag-and-drop: faster, works with keyboard and touch, and testable.
- Mission effect: guard vision cones and tags are shown only for characters the drone labelled "guard". A missed guard is invisible; a civilian false positive is marked red exactly like a guard. No model means no marks. The drone's accuracy on the characters it scanned is shown in the debrief and adds up to 500 points (README: "Score: stealth + time + your AI's accuracy").
- The game was restructured for three missions: Start → Briefing → Lab → Mission → Debrief (Next, Retry, Retrain in Lab) → Heist Complete; maps gained vault, console, terminal and locked-door cells.
Follow-up: the browser run showed every drone confidence at 100%, including a misclassified civilian. Measured k = 3/5/7: k = 5 reduces "100%" answers from 85% to 69% but lowers accuracy from 88.2% to 86.5%. Kept k = 3; documented that confidence (vote share) is overconfident but still informative (mean 0.98 when right, 0.77 when wrong).

- Lab: live training (~2 s), episode counter, ε, a 25-episode moving-average reward chart drawn on a canvas (no Chart.js dependency needed), policy arrows in every cell, the learned path, and a verdict that explains failures ("is touching a laser actually punished?").

Goal → drive delivered through the vent; laser → alarm and "LASER TRIPPED" after 3 s; circling → "DOG LOST". Debrief AI score = shortest safe path ÷ learned path length (1.0 when optimal).

  3. Inspecting the chunks showed the real bug: the sentence splitter broke at "Mr.", so the clue "…name of Mr." and "Varma's first robot…" were in different chunks. - `worker/llm-proxy.js` (Gemini, Groq backup): origin allow-list, 20 requests/hour/IP, JSON validation, prompt rebuilt server-side so clients cannot inject instructions, context truncated, key never returned. Tested with a mocked Gemini.
